# Merchant: справка по объектам

Здесь описаны данные и методы сервиса. Нужные изменения для ЛР1 перечислены в [TASK.md](TASK.md).
Часть методов уже реализована в заготовке, остальные добавляются по мере выполнения работ.

## Данные и поведение

`Merchant` описывает магазин, который принимает оплату.

| Объект | Данные и назначение |
|---|---|
| `Merchant(merchant_id, name, category, country)` | Магазин со статусом `ACTIVE`. Другие состояния — `SUSPENDED` и `CLOSED`. |
| `MerchantContext(channel)` | Канал оплаты: `POS` или `ONLINE`. Класс уже готов. |
| `MerchantService` | Находит магазин, проверяет его доступность и применяет правила приёма оплаты. |

Методы магазина — `suspend()`, `activate()`, `close()` и `availability()`. Метод `MerchantService.check(merchant_id, context) -> CheckResult` сначала проверяет доступность, затем дополнительные правила.

Категории `GROCERY`, `RESTAURANT`, `FUEL`, `TRAVEL`, `GAMBLING`, `OTHER` — условные значения проекта, не коды MCC. Страна задаётся двумя заглавными латинскими буквами. Обращений к внешним справочникам нет.

Общий интерфейс — `MerchantAcceptanceRule.check(merchant, context)`. `RestrictedCategoryRule(denied_categories)` запрещает указанные категории; `AcceptedChannelRule(channels)` разрешает указанные каналы. Категория `GAMBLING` сама по себе не означает обязательного отказа: это зависит от настройки. Сервис Fraud отдельно учитывает её при оценке риска.

Хранилище, контекст, перечисления, исключения и проверки допустимых значений уже реализованы.

## Работа с готовым кодом

Обращение к сервису выполняется через `app/api.py`. Разрешённые файлы указаны в [TASK.md](TASK.md).
Проверки используют подготовленные данные и не зависят от работы других групп.

Функции `create`, `make`, `call` и `view` связывают готовый API с реализацией. Используемые ими функции сервисного модуля должны сохранять сигнатуры. Сам `app/api.py` не редактируйте.

До ЛР5 сборка предоставлена готовой. Нужные объекты могут создаваться в сервисном модуле; `assembly.py` менять не нужно.

## Ошибки и результаты

`DomainError` содержит код ошибки. При отказе проверки состояние объекта не должно меняться.
Ошибка переданной зависимости не заменяется успешным результатом. Конкретные коды и примеры
приведены в задании и открытых тестах.
