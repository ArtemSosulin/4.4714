# ЛР2. Закрытие магазина и проверка данных

Вариант: **Merchant**.

## Что дано

Обычные операции работают, но объект пока принимает некорректные данные и допускает переход из закрытого состояния обратно в работу.

## Задание

### Шаг 1. Проверяйте имя и страну

Удаляйте пробелы по краям имени и отклоняйте пустое значение с кодом `INVALID_NAME`. Код страны должен состоять ровно из двух заглавных латинских букв. Используйте готовую проверку; ошибка — `INVALID_COUNTRY`.

### Шаг 2. Защитите переходы состояния

Разрешены только переходы `suspend(): ACTIVE -> SUSPENDED`, `activate(): SUSPENDED -> ACTIVE` и `close(): ACTIVE/SUSPENDED -> CLOSED`. Все остальные переходы, включая повтор действия, вызывают `INVALID_STATE`.

Сначала проверяйте исходный статус и только потом меняйте `_status`. Ошибка не должна оставлять объект в новом состоянии.

### Шаг 3. Сохраните правила доступности

Для закрытого магазина `availability()` возвращает `MERCHANT_CLOSED` и не изменяет объект. Проверки должны жить в `Merchant` и работать при прямом вызове, а не только через API или сервис.

## Примеры и границы

- `CLOSED` нельзя активировать.
- Повторный `suspend()` вызывает ошибку и сохраняет `SUSPENDED`.
- `"   "` недопустимо; `" Alice "` нормализуется.
- `"NL"` допустимо, `"NLD"` и `"nl"` вызывают `INVALID_COUNTRY`.
